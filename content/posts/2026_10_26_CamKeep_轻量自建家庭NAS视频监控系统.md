如今在家里装一两个网络摄像头，几乎成了许多家庭的刚需——有人为了看家防盗，有人为了随时看一眼熟睡的婴儿，还有人为了在上班时抓拍家里宠物的搞笑日常。

市面上的智能摄像头硬件往往几十到一百出头就能买到，性价比看似极高。但真正用上之后，许多人都会遇到几道躲不开的“坎”：

1. **无休止的云存储订阅套路**：不买云存储，历史录像就只能看十几秒甚至只有缩略图；如果家里装了三四个摄像头，一年光是交云存会员费就比摄像头本身还要贵。
2. **挥之不去的隐私安全隐忧**：家里的客厅、卧室、大门口实时画面，全部通过第三方厂商的云端中转和存储，隔三岔五爆出的“云端漏洞”或“监控泄露”新闻，让人心里总是不踏实。
3. **传统开源 NVR 又重又繁琐**：想在自己的 NAS 或软路由上自建 NVR（网络视频录像机）？市面上的传统方案要么配置复杂得像工业视频工程软件，要么对 CPU 和显卡性能要求苛刻，家里几十瓦的小主机跑上去风扇狂转、发热剧增，实在经不起长期 7×24 小时折腾。

正是出于**“想要一个极简、省电、好用且 100% 掌握在自己手中”**的初衷，我打磨了这款轻量级自托管 NVR——[CamKeep](https://github.com/r0n9/camkeep)。

今天这篇文章不聊晦涩的底层音视频编解码算法，就单纯从家庭用户和 HomeLab 爱好者的日常视角，聊聊它是如何帮我们轻松接管家庭安防的。

## 什么是 CamKeep？

简单来说，**CamKeep 是一个专为家庭 NAS、迷你主机和小服务器设计的轻量级自建网络视频录像系统。**

它的核心任务非常纯粹：
- **接入流**：把家里各个品牌（海康、大华、TP-Link、各种海思/雄迈方案等）摄像头的视频流统一聚合起来；
- **录下来**：按照你设定的时间规则，安静无感地把视频持久化存到你的 NAS 硬盘上；
- **查得到**：提供一个清爽易用的 Web 网页端，让你随时随地像刷短视频一样顺滑地拖动时间轴回看录像。

它没有庞杂的企业级安防架构，也不强求高昂的硬件配置。只要你的设备支持运行 Docker（无论是群晖、威联通、Unraid、TrueNAS，还是装了 Linux 的小主机、N1 盒子、树莓派），一条命令就能轻松跑起来。

## 为什么选择 CamKeep？日常使用中的几大亮点

### 1. 100% 局域网本地优先，彻底告别云端与订阅

CamKeep 在设计之初就确立了**“内网安全、本地优先”**的原则：
- **零外部依赖**：它不需要注册任何外部云端账号，不依赖厂商的云服务中转，更不会向外界上传你的任何视频片段与设备信息；
- **免订阅费**：你的存储空间有多大，录像就能存多久。硬盘满了？系统会自动按设定的天数循环清理最旧的片段，全程全自动；
- **本地权限可控**：系统内置了本地用户与权限管理，可以为家人创建只读账号，甚至单独限制某个账号只能看门口摄像头，兼顾便利与隐私。

### 2. 极致的低功耗设计，老旧小主机也能轻松常开

对于 24 小时开机的家庭设备，电耗和发热是必须考虑的现实问题。很多传统 NVR 动辄在后台对视频进行二次转码，导致 CPU 占用率居高不下。

CamKeep 深度复用了开源流媒体项目 `go2rtc` 的流处理能力，录制时默认采用**“直接流拷贝（Stream-Copy）”**技术——摄像头推过来什么格式，系统就原汁原味地分片写入磁盘，CPU 几乎只需要处理基础的 I/O 写入。这意味着即便是在几瓦功耗的软路由、老款 ARM 设备或低配 J4125 / N100 小主机上接入多路 2K/4K 摄像头，CPU 占用通常也仅有个位数，设备完全不会发烫。

### 3. 像商用 App 一样好用的 24 小时时间轴回放

以前很多简陋的自建录像方案，回放时往往是一堆零碎的 `.mp4` 文件列表，想找一段昨天下午 3 点的画面得翻好几页、挨个点开试看，体验极其糟糕。

CamKeep 在网页控制台里内置了**可拖拽的 24 小时连续时间轴**：
- 支持鼠标滚轮缩放、移动端双指手势缩放，可以在“全天视图”与“分钟精细视图”之间随意平滑缩放；
- 点到哪里，画面直接秒级定位播放；
- 更贴心的是**动检事件高亮标记**：即便你是 24 小时全天候连续录像，系统也能在检测到画面有人或车走过时，在时间轴上叠加不同颜色的小色块。回看时扫一眼时间轴，哪里有动静一清二楚，再也不用快进几小时“大海捞针”。

### 4. 丰富的事件录像策略：帧差与 ONVIF 联动

除了常规的“定时录像”与“全天录像”，家庭监控经常需要“动检录像”（只录有动静的时刻，极度节省磁盘空间）。

CamKeep 支持多种事件触发源：
- **内置轻量帧差检测**：针对普通的纯 RTSP 摄像头，后台用极低的采样率检测画面变化；
- **ONVIF PullPoint 硬件直通**：如果摄像头本身支持 ONVIF 事件上报，CamKeep 可以直接接收摄像头的硬件动检信号，完全不耗费宿主机的计算资源；
- **Time-Shift 时光倒流缓存**：很多时候画面出现变化时，往往“关键动作”已经发生了。CamKeep 支持预录缓存引擎，在事件触发时能连同**发生前几秒**的缓冲画面一起打包成事件视频，完整捕捉来龙去脉。

### 5. 统一的设备控制与超低延迟直播

如果你的摄像头支持机械云台旋转（PTZ）、对焦或光学变焦，CamKeep 在 Web 控制台就能直接进行遥控操作，免去在手机上翻找各家私有 App 的繁琐。同时得益于 go2rtc 的加持，实时预览时延能压到几十毫秒以内的 WebRTC 级别，点开即看，几乎感觉不到延迟。

## 3 分钟快速上手

部署 CamKeep 非常简单，推荐直接使用 Docker 或 Docker Compose。

### 第一步：准备存储目录

在你的 NAS、硬盘阵列或服务器上找一个空间充足的路径，建立好配置目录和录像目录。例如：

```bash
mkdir -p /vol1/CamKeep/config
mkdir -p /vol1/CamKeep/records
```

### 第二步：编写 `docker-compose.yml`

在同级目录下新建一个 `docker-compose.yml` 文件：

```yaml
services:
  camkeep:
    image: ghcr.io/r0n9/camkeep:latest
    container_name: camkeep
    restart: unless-stopped
    network_mode: "host"           # 推荐 host 模式，便于 WebRTC 低延迟直播与局域网设备探测
    shm_size: "512m"               # 预录缓存共享内存建议设为 512MB 以上
    environment:
      - TZ=Asia/Shanghai
      - CAMKEEP_AUTH_PASSWORD=admin # 设置你的初始管理员密码
    volumes:
      - ./config:/app/config       # 存放配置文件与系统状态
      - ./records:/app/records     # 存放历史录像与最新抓拍封面
```

然后在终端执行启动命令：

```bash
docker compose up -d
```

### 第三步：添加摄像头，开始录制

1. 启动完成后，打开浏览器访问 `http://<你的NAS IP>:9110`；
2. 输入默认用户名 `admin` 和上面配置的初始密码登录系统；
3. 进入**「配置管理」**页面，系统提供了非常友好的图形化表单，只需填入摄像头 ID 与对应的 RTSP 地址（例如 `rtsp://admin:password@192.168.1.100:554/stream`），选择开启录像即可；
4. 回到首页的**「实时节点」**看板，稍等几秒就能看到摄像头的实时画面、当前状态和自动录制进度。

## 结语

折腾家庭 HomeLab 和自建服务的乐趣，往往不在于堆砌多么宏大复杂的架构，而在于**用最轻巧、可控的技术，切实解决生活中的实际需求**。

CamKeep 并不是一个试图去和海康、大华企业级安防云相抗衡的重型软件，它更像是一个守候在家庭角落里默默耕耘的“数字录像管家”：它安安静静，只消耗极低的资源，不打扰你，也不向任何云端上传哪怕一帧画面；但当你想回顾某一天某个时间点的院子、门口或是小猫小狗的小插曲时，它总能清晰、顺畅地为你呈现出来。

如果你家里正好有一台闲置的 NAS 或小主机，也有几个正在使用的网络摄像头，不妨把 CamKeep 跑起来体验一下。
